# 策略分析：聚类-意图关联 vs 分层关键词扩展

**创建时间**: 2026-04-10
**项目**: IntentWeight
**类型**: 策略决策分析
**状态**: 架构评估

---

## 核心问题

在 IntentWeight 的检索架构设计中，哪种策略更有效？

- **聚类-意图关联策略**：用户查询 → 意图分类 → 意图类别权重 → 检索策略
- **分层关键词扩展策略**：用户查询 → 关键词抽取 → 语义扩展 → 分层检索

---

## 本质区别

```
聚类-意图关联策略:
用户查询 → 意图分类 → 意图类别权重 → 检索策略
           (What is the user's intent?)
           从【用户视角】分类意图，解决"用户想要什么"

分层关键词扩展策略:
用户查询 → 关键词抽取 → 语义扩展 → 分层检索
           (What does the query mean?)
           从【查询视角】扩展语义，解决"查询意味着什么"
```

**关键洞察**：
- 聚类-意图回答的是"用户属于哪类人"
- 分层关键词回答的是"查询本身包含什么语义"

---

## 多维度对比

| 维度 | 聚类-意图关联 | 分层关键词扩展 |
|------|---------------|----------------|
| **召回能力** | 依赖意图覆盖度，新意图需重新聚类 | 自动扩展语义空间，泛化能力强 |
| **精确度** | 意图分类准确度是瓶颈 | L1 精确匹配保底，L2/L3 可控扩展 |
| **冷启动** | 新意图无历史反馈时失效 | 语义扩展提供先验，冷启动表现好 |
| **可解释性** | 黑盒：意图→权重，难追溯 | 白盒：每层关键词权重可追溯 |
| **计算成本** | 意图聚类预计算，更新成本高 | 关键词扩展实时计算，可缓存 |
| **领域适应** | 需要领域意图定义 | 仅需领域本体/词汇资源 |
| **长尾处理** | 需要足够样本聚类 | 语义扩展自动覆盖 |

---

## 为什么分层关键词更有效？

### 1. 意图的"粒度悖论"

聚类-意图策略必须在粒度选择上做出妥协：

```
粗粒度意图（如"产品查询"）:
- 召回高，但噪声多
- 难以区分具体需求

细粒度意图（如"iPhone 15 Pro 价格查询"）:
- 精确，但覆盖度低
- 样本稀疏，学习困难
```

**分层关键词的解决方案**：通过 L1/L2/L3 三层自然解决粒度问题：

```
L1 (核心层) = 细粒度精确匹配
L2 (上位层) = 中粒度泛化召回
L3 (下位层) = 实例级补充
```

三层权重动态调整，无需在粒度上做固定选择。

---

### 2. 召回-精确的动态平衡

**聚类-意图**：
- 一个意图对应一套固定权重
- 无法根据具体查询调整召回-精确策略

**分层关键词**：
- 每次查询动态计算三层权重
- 可以根据查询特征调整召回-精确平衡

**示例**：

| 查询 | 用户需求 | 最优策略 |
|------|----------|----------|
| "iPhone 价格" | 明确，精确 | L1 权重高 |
| "买手机推荐" | 模糊，探索 | L2/L3 权重高 |
| "华为和小米对比" | 结构化，全面 | L1/L2/L3 均衡 |

---

### 3. 意图的"组合爆炸"问题

```
用户意图空间 = 意图类型 × 领域 × 细节层次 × 时间 × ...

聚类维度: 数百个意图类别 → 维度爆炸
分层关键词: 数十个核心词 + 自动扩展 → 可控增长
```

**关键差异**：
- 意图类别需要人工定义或从数据中学习，组合爆炸后难以维护
- 关键词空间有限，扩展规则可通过本体/LLM 自动化

---

### 4. 反馈信号的稀疏性与复用

**聚类-意图的问题**：

```
"手机价格查询" → Intent_001
"电脑价格查询" → Intent_002
两者反馈无法复用
```

**分层关键词的优势**：

```
"手机价格" → ["价格"] + ["手机"]
"电脑价格" → ["价格"] + ["电脑"]
"价格"关键词权重可复用
```

**结论**：关键词级权重的反馈复用率远高于意图级权重。

## 聚类-意图策略的适用场景

聚类-意图策略并非无用，在以下场景更具优势：

| 场景 | 特点 | 优势 |
|------|------|------|
| **封闭域** | 意图类型有限且明确 | 意图覆盖完整，分类准确 |
| **任务型对话** | 需要触发特定工作流 | 意图直接映射到 Action |
| **冷启动极早期** | 完全没有领域词汇资源 | 意图框架可人工定义 |
| **客服机器人** | 意图有限且稳定 | 易于维护和监控 |

**关键区别**：开放域 vs 封闭域

```
开放域 RAG（IntentWeight 目标场景）:
- 查询类型不可穷尽
- 用户意图多样且动态变化
- 需要强泛化能力
→ 分层关键词更优

封闭域任务（如客服机器人）:
- 意图类型可穷尽
- 工作流固定
- 需要精确意图匹配
→ 聚类-意图更优
```

## 策略融合方案

两者不是互斥的，可以融合：

```
用户查询
    │
    ├─────────────────────────────┐
    │                             │
    ▼                             ▼
分层关键词扩展              意图分类（辅助）
(L1/L2/L3)                  (粗粒度意图)
    │                             │
    │                             │
    ▼                             │
关键词权重学习 ◄─────────────────┘
(主策略，细粒度)             (提供意图先验)
    │
    ▼
分层检索融合
```

### 融合方式

**意图信号 → Context Feature**：

```python
def build_context(query, user_id, history):
    # 关键词特征（主）
    keywords = extract_keywords_hierarchy(query)
    keyword_features = encode_keywords(keywords)
    
    # 意图特征（辅助）
    intent = classify_intent(query)  # 粗粒度意图
    intent_feature = encode_intent(intent)
    
    # 融合
    context = concat([
        keyword_features,  # 主特征
        intent_feature,    # 辅助特征
        user_features,
        time_features
    ])
    
    return context
```

**意图引导扩展策略**：

```python
def expand_keywords(keywords, intent):
    """根据意图调整扩展策略"""
    
    # 不同意图有不同的扩展深度
    expansion_config = {
        'product_query': {'L2_depth': 2, 'L3_depth': 3},
        'comparison': {'L2_depth': 1, 'L3_depth': 2},
        'informational': {'L2_depth': 3, 'L3_depth': 1}
    }
    
    config = expansion_config.get(intent, default_config)
    
    return {
        'L1': keywords['L1'],
        'L2': expand_hypernyms(keywords['L1'], depth=config['L2_depth']),
        'L3': expand_hyponyms(keywords['L1'], depth=config['L3_depth'])
    }
```

## 决策结论

### 推荐：分层关键词扩展作为主策略

**理由**：

1. **粒度自适应**：三层架构天然解决召回-精确平衡
2. **泛化能力强**：语义扩展自动覆盖长尾查询
3. **反馈利用高**：关键词级权重可跨查询复用
4. **冷启动友好**：语义扩展提供先验知识
5. **可解释性强**：权重来源可追溯

### 意图分类作为辅助信号

**作用**：
- 提供粗粒度意图先验
- 引导扩展策略选择
- 辅助冷启动场景

## 实施建议

### 当前状态（聚类-意图）

IntentWeight 目前主要采用聚类-意图关联策略：
- 意图通过 embedding 聚类定义
- LinUCB 学习意图级权重
- 检索策略与意图绑定

### 演进路径

```
Phase 1: 增加分层数据处理层
         - 添加关键词抽取模块
         - 实现 L1/L2/L3 分层存储

Phase 2: 改造权重学习层
         - 从意图级权重 → 关键词级权重
         - 意图作为 Context Feature 保留

Phase 3: 重构检索融合层
         - 实现分层检索 + 加权融合
         - 支持动态召回-精确平衡

Phase 4: A/B 测试验证
         - 对比原方案与新方案效果
         - 收集用户反馈优化
```
