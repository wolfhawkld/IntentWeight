# IntentRoute Overall Scientific Review

> Review date: 2026-07-12<br>
> Reviewer perspective: GPT-5.6-sol max, scientific and systems-research audit<br>
> Scope: current `pre_validation` manuscript, implementation, experiment artifacts,
> statistical evidence, cross-dataset results, and submission package<br>
> Status: read-only assessment snapshot; recommendations in this document have not
> yet been applied to the manuscript or code

## 1. Overall Assessment

The project already has the foundation of a substantial engineering-oriented
AI/RAG journal paper. The research problem is practical, the experiment coverage
is broad, adverse findings are reported rather than hidden, and artifact
traceability is unusually strong. The central research direction does not need
to be replaced, and neither manifold-inspired geometry nor LinUCB needs to be
removed.

The paper is not yet submission-ready, however. The highest-priority issues are
not a lack of experiment count. They are several mismatches between the method
description and the implementation, plus the fact that repeated-query online
feedback experiments do not directly establish generalization to unseen
queries. A rigorous reviewer could reasonably request major revision on these
grounds.

Qualitative assessment:

- Research relevance and engineering value: strong.
- Experiment breadth and reproducibility: strong.
- Statistical treatment and reporting of negative evidence: medium-to-strong.
- Method novelty: moderate; strongest as a systems mechanism and evaluation
  protocol contribution.
- Strength of manifold or theoretical claims: bounded but acceptable if phrased
  precisely.
- Current submission readiness: substantial revision required.

## 2. P0 Method-to-Code Consistency Issues

### 2.1 The LinUCB Feature Description Is Broader Than the Implementation

Section 3.5 states that the controller uses dense-score concentration and
margin, BM25 strength, route agreement, local geometry, feedback state, and
budget state in addition to the query representation.

The current implementation primarily passes the PCA projection of the query
embedding to LinUCB:

- `paper/experiments/scripts/linucb_online_baseline.py:81`
- `paper/experiments/scripts/linucb_cost_aware_routing.py:660`

Arm value, score margin, pull maturity, and semantic drift are subsequently used
to construct route confidence or gating signals. The inspected implementation
does not concatenate all feature groups listed in the manuscript into the
LinUCB context vector.

Recommended resolution: rewrite the method description to match the tested
implementation. Expanding the feature vector now would define a different
method and require rerunning the core experiment families.

### 2.2 The Cost-Penalized Reward Equation Is Not Implemented

Section 3.6 defines the conceptual reward as:

```text
r_t = g_t - lambda * c_t
```

The implementation instead obtains a binary evidence-hit reward from either the
selected cluster route or final fused ranking and applies the simulated trust
weight before updating LinUCB:

- `paper/experiments/scripts/linucb_cost_aware_routing.py:828`

No token or candidate-cost term controlled by `lambda` was found in this reward
update. Candidate cost and final-context tokens are measured elsewhere.

Recommended resolution: remove the cost-penalized reward equation and state
that cost control is implemented through route gating and independently
calibrated evidence budgeting. Implementing the equation would again create a
new method requiring broad reruns.

### 2.3 Repeated-Query Adaptation Is Not Unseen-Query Generalization

Several main experiments iterate over the same query population for multiple
prequential epochs:

- `paper/experiments/scripts/linucb_cost_aware_routing.py:645`

The manuscript correctly acknowledges that these runs simulate repeated
interaction and are not IID held-out generalization results. Nevertheless, a
query encountered in a later epoch can indirectly benefit from feedback
generated by its earlier occurrence. Budget calibration/test separation does
not by itself make route-policy training held out.

The highest-value missing experiment is therefore a frozen unseen-query test:

1. Update LinUCB and feedback memory only on history or calibration queries.
2. Freeze every policy and feedback state.
3. Evaluate previously unseen test queries in one pass.
4. Compare with static-nearest geometry, no-feedback routing, full fusion, and
   dense retrieval.

If this succeeds, it supports transferable feedback adaptation. If it does not,
the method should be explicitly positioned as adaptation for recurring-query or
personalized interaction streams.

### 2.4 The Budget Operator Is Not Always a Contiguous Prefix

Section 3.9 describes the output as the longest ranked prefix satisfying the
token budget. The implementation preserves a mandatory prefix, then may skip an
oversized later chunk and admit a smaller chunk farther down the ranking:

- `paper/experiments/scripts/task37_context_budget_search.py:72`

The accurate term is an order-preserving budgeted subset with a mandatory
prefix, not necessarily the longest contiguous prefix. The manuscript should
also distinguish the source ranking used to define each policy's budget from
the dense top-10 denominator used for reported savings.

### 2.5 Experiment Protocol Versions Need a Single Audit Table

The method gives three prequential epochs as the default, whereas parts of the
later common protocol use eight epochs. Formal experiment families also differ
between `cluster_only` and `final_fused` reward attribution.

A protocol table should identify, for every result family:

- dataset and corpus scale;
- query split and calibration protocol;
- number of epochs and seeds;
- reward attribution;
- routing mode and rescue routes;
- embedding backbone;
- context-budget policy.

This is necessary to prevent results from different protocol generations being
interpreted as directly matched experiments.

## 3. Core Scientific Challenges

### 3.1 Feedback Is Useful, but Its Centrality Is Not Fully Established

On the technology/search 100k control, static-nearest geometry obtains route
reward 0.8563 and cluster hit 0.8870, while learned full multi-route obtains
0.6790 and 0.5766. Feedback improves route quality relative to random or
no-feedback routing, but it has not been shown to outperform the strongest
static geometry policy.

Consequently, the current evidence supports feedback as a recovery,
personalization, or adaptation mechanism rather than the universal source of
first-pass route quality. A non-stationary preference, domain-shift, or changing
feedback experiment would provide the clearest justification for retaining
`feedback-adaptive` as a central contribution.

### 3.2 Route Confidence Does Not Directly Predict Safe Compression

Task65.1-65.3 delineate this boundary clearly. Geometry plus feedback does not
show superior safe-compression discrimination, and route confidence has near-zero
correlation with oracle compression headroom. Compression safety is primarily
determined by the position and token location of relevant evidence after
fusion.

The supported mechanism is:

```text
geometry and feedback
    -> route confidence and route shape
    -> routed/fused evidence-pool quality

independent calibration
    -> final context budget

evidence pool + calibrated budget
    -> bounded quality/context-cost trade-off
```

The unsupported mechanism is:

```text
route confidence -> direct prediction of safe token compression
```

The paper should preserve this separation throughout the title, abstract,
method, results, and conclusion.

### 3.3 Cross-Fitted Results Should Carry More Weight Than One Favorable Split

The normalized five-fold evaluation reports the following IntentRoute Hit
changes and token savings from 100k through 638k:

- 100k: -1.06 percentage points / 4.16% saving.
- 200k: +1.40 percentage points / 16.07% saving.
- 400k: +0.00 percentage points / 14.50% saving.
- 638k: +0.28 percentage points / 15.23% saving.

Strict seed-level 1pp non-inferiority is not consistently established. The
20-partition audit also shows greater instability at 100k and 400k than at 200k
and 638k.

The main abstract and headline table should therefore foreground the out-of-fold
range and describe the original pre-specified split as an important but
split-specific result. `No statistically detectable difference` must not be
used as a synonym for equivalence or non-inferiority.

The 1pp non-inferiority margin also needs a substantive application-level
justification. Multiple policy, scale, backbone, and metric comparisons should
either be identified as exploratory or controlled within predeclared families.

### 3.4 Current Efficiency Evidence Is Context-Level, Not End-to-End

The strongest cost claim concerns final evidence-context tokens. IntentRoute may
still execute dense retrieval, BM25, cluster-local retrieval, fusion, and cache
preparation. Therefore lower LLM input cost does not necessarily imply lower
end-to-end latency, energy, memory, or total serving cost.

The paper should report at least:

- offline index/cache construction time;
- per-query retrieval and routing latency;
- peak memory or resident cache size;
- dense/BM25/cluster invocation rates;
- final context tokens;
- amortized cost under a stated deployment workload.

Without this table, `context-efficient evidence selection` is more accurate than
an unrestricted claim of system efficiency.

### 3.5 Geometry Is a Bounded Motivation, Not a Manifold Proof

High nearest-cluster hit in the same embedding/PCA space shows that clustering
preserves useful semantic neighborhoods. It does not establish a manifold
theorem, and part of this association is expected because both the diagnostic
and retrieval policy use the same representation.

The manifold-inspired framing remains reasonable if described as a design
hypothesis and structural diagnostic. Optional stronger evidence could include
intrinsic-dimension estimates, neighborhood enrichment against matched random
projections, local linearity/trustworthiness measures, or confirmation using an
independent relevance model.

### 3.6 Novelty Must Be Positioned as a Systems Contribution

KMeans, LinUCB, BM25, dense retrieval, reciprocal-rank fusion, and budget
calibration are individually established components. The defensible novelty is
their controlled composition and attribution:

- geometry-structured candidate routing;
- feedback-adaptive route confidence;
- explicit dense/BM25 rescue;
- independently calibrated evidence budgets;
- experiments that separate route quality, fused quality, and final context
  cost;
- extensive negative controls and frozen/cross-fitted evaluation.

Recent adjacent work increases the need for precise positioning:

- [AttnComp](https://aclanthology.org/2025.findings-emnlp.449/)
- [LLM-Independent Adaptive RAG](https://aclanthology.org/2025.emnlp-main.439/)
- [RouteRAG](https://aclanthology.org/2026.findings-acl.1502/)
- [Know Before You Fetch](https://arxiv.org/abs/2606.29959)
- [AdaGReS](https://arxiv.org/abs/2512.25052)

The related-work section should explicitly state that IntentRoute is not the
first bandit or adaptive RAG system and explain its distinct evidence-attribution
and calibrated-budget protocol.

## 4. Evidence That Is Already Strong

- Route quality, fused retrieval quality, and final-context cost are separated
  rather than treated as one metric.
- Random, no-feedback, static-nearest, dense budget-only, K-sensitivity,
  split-sensitivity, cross-fit, and multi-judge controls form a substantial
  defensive evidence chain.
- Task65 reports evidence that contradicts an earlier causal interpretation
  instead of suppressing it.
- Multi-backbone and cross-domain experiments support a bounded transferable
  trade-off rather than a single-model artifact.
- Experiment outputs, reports, scripts, and manuscript tables have unusually
  strong traceability.
- The manuscript already avoids claiming real human feedback, universal dense
  replacement, strict answer-quality superiority, or a formal manifold theorem.

These properties make the project scientifically credible even where strict
non-inferiority is not established.

## 5. Recommended Core Claim

The strongest claim supported by the complete evidence is:

> IntentRoute is a local-geometry-inspired evidence-routing controller that can
> adapt its route state under simulated feedback. Dense and lexical rescue
> protect candidate-pool quality, while an independently calibrated context
> budget exposes a bounded quality-context-cost frontier across multiple corpus
> scales, embedding backbones, and domains.

The paper should not claim that:

- route confidence directly predicts whether a query is safely compressible;
- learned LinUCB universally outperforms static nearest-centroid routing;
- every seed, split, scale, and domain is non-inferior to dense retrieval;
- manifold geometry directly causes token saving;
- final-context token saving is automatically equivalent to end-to-end system
  efficiency.

This is a tightening of causal precision, not a replacement or collapse of the
main research direction.

## 6. Prioritized Revision Plan

### P0: Required Before Submission

1. Align the feature, reward, and budget descriptions with the tested code.
2. Add a consolidated experiment-protocol table.
3. Run a frozen-policy, one-pass unseen-query feedback-generalization test.
4. Complete the formal science 400k common-protocol experiment.
5. Move five-fold out-of-fold evidence into the primary statistical narrative.
6. Report end-to-end latency, memory, preprocessing, and amortized serving cost.
7. Regenerate the review and journal packages after Task69 is finalized.
8. Replace the non-final Figure 1 and revalidate physical dimensions and font
   embedding for all submission figures.

### P1: High-Value Strengthening

1. Add one current strong adaptive context-selection or compression baseline
   under the same ranking and budget protocol.
2. Add a non-stationary or preference-shift experiment if feedback adaptation
   remains central in the title.
3. Add one modern strong open embedding or late-interaction retrieval backbone.
4. Strengthen the geometry diagnostic with a representation-independent or
   intrinsic-dimension analysis.
5. Justify the 1pp margin and add hierarchical or multiplicity-aware statistical
   reporting where appropriate.

### P2: Material to Reduce or Move

1. Move historical smoke tests and implementation-evolution narrative to the
   supplement or repository documentation.
2. Keep detailed K grids and secondary arm diagnostics in the supplement.
3. Do not import all pre-validation datasets into the main paper unless each
   answers a distinct scientific question.
4. Do not add every remaining LoTTE domain merely to increase dataset count;
   finish science 400k first, then add at most one or two hypothesis-driven
   domains if a genuine coverage gap remains.
5. Consolidate repeated caveats while preserving the complete evidence chain
   and core narrative.

## 7. Title Assessment

The current title is defensible, but `Route Confidence for Efficient Evidence
Selection` can be read as claiming that route confidence directly controls safe
compression. A more implementation- and evidence-aligned candidate is:

> **IntentRoute: Geometry-Guided and Feedback-Adaptive Routing with Calibrated
> Evidence Budgets**

This retains the preferred `IntentRoute`, `Geometry-Guided`, and
`Feedback-Adaptive` concepts while making the independent budget mechanism
explicit. Any title change should be discussed before modifying the manuscript.

## 8. Final Decision

The existing evidence supports retaining the principal research direction and a
meaningful quality-context-cost claim. The project does not require wholesale
claim downgrading, removal of manifold inspiration, or removal of LinUCB.

The paper does require:

- exact method-to-code alignment;
- an unseen-query boundary test for feedback generalization;
- a more conservative statistical headline centered on cross-fitted evidence;
- explicit separation of context efficiency from total system efficiency; and
- updated positioning against recent adaptive RAG and context-selection work.

After these changes, the work is best presented as a rigorous, bounded systems
contribution rather than a universal theoretical or non-inferiority result.
