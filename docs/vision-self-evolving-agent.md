# 项目愿景：自进化 Agent 系统
# Project Vision: Self-Evolving Agent System

**日期 / Date**: 2026-04-20
**核心理念 / Core Philosophy**: 构建一个可以快速且持续自优化的 Agent 系统，根据用户反馈不断进化，实现系统-用户双赢

---

## 设计哲学
## Design Philosophy

企业知识库系统的核心挑战不是"一次性做好"，而是"如何持续变好"。

传统 RAG 系统是静态的 — 部署后效果固定，优化靠人工调参。本项目追求的是一个**自进化系统**：每一次用户交互都让系统变得更好，不需要人工干预。

```
传统 RAG：
  部署 → 使用 → 效果固定 → 人工优化 → 重新部署 → ...

自进化 Agent：
  部署 → 使用 → 用户反馈 → 自动优化 → 效果提升 → 更好的使用体验 → 更多反馈 → ...
         ↑                                                              ↓
         └──────────────── 正向飞轮 ────────────────────────────────────┘
```

---

## 自优化闭环
## Self-Optimization Loop

系统通过四个层级持续进化，每个层级的优化速度和作用范围不同：

```
┌─────────────────────────────────────────────────┐
│              实时优化（每次交互）                  │
│                                                 │
│  用户提问 → Agent 决策 → 检索 → 回答             │
│      ↑                           ↓              │
│      │    LinUCB 权重更新 ← 用户反馈             │
│      │    (显式👍👎 + 隐式行为 + 上下文追问)      │
│      └────────────────────────────┘              │
├─────────────────────────────────────────────────┤
│              会话级优化（每次对话）                 │
│                                                 │
│  用户纠正 → 别名提取 → 查询扩展字典更新           │
│  "LC RD就是液晶研发部门" → 下次查询自动扩展       │
├─────────────────────────────────────────────────┤
│              每日优化（批量分析）                   │
│                                                 │
│  对话历史 → LLM Insight 提取                     │
│  → 别名字典补充                                  │
│  → 事实纠正入向量库                               │
│  → 知识缺口报告                                  │
├─────────────────────────────────────────────────┤
│              周期优化（定期重估）                   │
│                                                 │
│  全部历史数据 → 批量参数重估 → LinUCB 基线校准    │
│  新文档入库 → 聚类重建 → 聚类结构更新             │
└─────────────────────────────────────────────────┘
```

## 系统-用户双赢机制
## System-User Win-Win Mechanism

### 用户侧收益
### User Benefits

| 使用次数 | 用户体验变化 |
|---------|------------|
| 首次使用 | 基础 RAG 检索，靠冷启动先验提供合理结果 |
| 5-10 次 | LinUCB 开始学会用户常问的领域，检索更精准 |
| 30+ 次 | 别名字典积累，模糊查询也能命中，查询扩展生效 |
| 100+ 次 | 系统深度理解该用户群体的检索偏好，几乎不需要多轮澄清 |

### 系统侧收益
### System Benefits

| 数据积累 | 系统能力变化 |
|---------|------------|
| 0 条反馈 | 冷启动先验 + LLM 通用能力 |
| 10+ 条 | LinUCB 脱离冷启动，开始个性化 |
| 50+ 条 | 别名字典初具规模，Insight 提取有价值 |
| 200+ 条 | 可训练 BERT Reward Model，reward 信号质量跃升 |
| 500+ 条 | 可训练 BERT 意图分类器，省掉 LLM 决策调用 |
| 1000+ 条 | 可尝试多步 RL，系统学会主动追问和规划 |

### 双赢飞轮
### Win-Win Flywheel

```
系统效果好 → 用户更愿意用 → 产生更多反馈
     ↑                           ↓
 系统持续优化 ← 更多数据积累 ← 更多交互
```

关键在于：**用户不需要刻意"训练"系统**，正常使用本身就是训练过程。点赞点踩、追问纠正、甚至只是浏览和复制，都在为系统提供优化信号。

## 对企业 AI 应用的认知
## Insights on Enterprise AI Applications

### 不存在通吃方案
### No One-Size-Fits-All Solution

企业内部数据的本质特点决定了不可能有一个预训练模型能通吃所有业务：

- **数据是私有的** — 没有任何预训练模型见过企业内部文档
- **术语是专属的** — 每家企业有自己的缩写、黑话、命名规范
- **流程是独特的** — 审批流程、组织架构、业务规则各不相同
- **需求是动态的** — 业务变化、人员调整、政策更新

### 正确定位：可适应的框架
### Right Positioning: Adaptable Framework

企业 AI 应用的正确定位不是"找一个通吃的模型"，而是**搭一个能持续适应的框架**：

```
通用能力层：  LLM (Azure/腾讯) — 语言理解和生成，开箱即用
    ↓
领域适配层：  向量库 + 聚类 — 把企业文档组织成可检索的结构
    ↓
持续优化层：  LinUCB + 反馈 — 从用户行为中学习这个企业的特定模式
    ↓
知识沉淀层：  别名字典 + Insight — 把学到的领域知识固化下来
```

框架是通用的，但里面填充的数据、学到的权重、沉淀的知识是每个企业独有的。换一个业务领域，框架不用换，重新跑一遍数据构建 + 积累反馈就行。

### 泛化性的务实态度
### Pragmatic View on Generalization

对于不同领域、不同场景、不同用户行为差异，任何数据驱动方法（包括 RL）都存在泛化问题。务实的应对策略是：

- **LLM 负责泛化** — 处理没见过的查询类型，兜底不失效
- **LinUCB 负责优化** — 在已知模式上越来越准
- **两者互补** — LLM 的泛化能力兜底 LinUCB 的泛化短板

系统不会因为 LinUCB 泛化不足而彻底失效，最多是"回退到全量检索"，用户体验不会比没有 LinUCB 时更差。

## 技术选型原则
## Technology Selection Principles

1. **数据效率优先** — 企业场景数据量有限，选择对数据需求最低的方法（LinUCB > PPO）
2. **在线学习优先** — 每次交互都能学，不等批量数据（Bandit > 离线训练）
3. **可解释优先** — 能说清"为什么选了这个聚类"（线性模型 > 黑箱神经网络）
4. **渐进式复杂度** — 从简单开始，数据够了再加复杂度（规则 → Bandit → BERT → RL）
5. **LLM 兜底** — 优化层失效时，LLM 通用能力保证基本可用

## IntentWeight 研究的定位
## Positioning of IntentWeight Research

本项目的 IntentWeight 研究（LinUCB + 意图聚类 + 反馈驱动权重学习）研究的不是某个领域的具体方案，而是**自适应框架本身的机制**：

- 如何做语义聚类来组织检索空间
- 如何用 Bandit 算法从反馈中学习检索偏好
- 如何设计多维反馈信号（显式 + 隐式 + 上下文）
- 如何处理冷启动（先验 + 热启动）
- 如何防止反馈投毒（用户信誉评分）

这些机制是领域无关的，可以应用到任何企业知识库场景。
