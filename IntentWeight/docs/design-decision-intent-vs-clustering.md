# IntentWeight 设计决策：意图分类 vs 语义聚类

**创建时间**: 2026-03-29
**来源**: Damon 与 Outis 关于意图分类与 RAG 数据关联的讨论

---

## 核心问题

> 意图分类能否有效筛选 RAG 数据？

---

## 两种思路对比

### 思路 A：问题意图 → 数据意图匹配

```
用户问题 → 意图分类 (Speech Act 5类)
                        ↓
RAG 数据 → 意图标注
                        ↓
          匹配: 问题意图 ∩ 数据意图 → 召回
```

**问题分析**：

```
意图分类粒度 = 5 类 (Speech Act)

RAG 数据分布:
  Chunk 1: [Directive: 0.6, Assertive: 0.5, Commissive: 0.3]
  Chunk 2: [Directive: 0.5, Assertive: 0.6, Commissive: 0.2]
  Chunk 3: [Directive: 0.4, Assertive: 0.4, Expressive: 0.1]
  ...
  Chunk N: [Directive: 0.5, Assertive: 0.5, ...]

用户问题意图: Directive

筛选结果:
  几乎所有 Chunk 的 Directive 分数都 > 0.3
  → 筛选效果 ≈ 无筛选
  → 召回 ≈ 全 RAG 数据
```

**结论**：意图分类粒度太粗，无法有效区分 RAG 数据。

---

### 思路 B：聚类 → 数据类型匹配

```
RAG 数据 → 语义聚类 → 数据类型标签
                        ↓
用户问题 → 聚类类型识别
                        ↓
          匹配: 问题类型 ∈ 数据类型 → 召回
```

**特点分析**：

```
聚类类型数量 = 可调 (例如 50 类)

聚类结果:
  Cluster 1: 银行转账相关 chunk (200个)
  Cluster 2: 信用卡申请相关 chunk (150个)
  Cluster 3: 报销流程相关 chunk (100个)
  ...
  Cluster 50: 密码重置相关 chunk (80个)

用户问题 → 识别为 Cluster 3
筛选结果: 只召回 Cluster 3 的 100 个 chunk
→ 筛选效果明显
```

---

## 核心差异对比

| 维度 | 思路 A (意图分类) | 思路 B (聚类) |
|------|------------------|--------------|
| **分类来源** | 人类认知定义 | 数据驱动发现 |
| **类别数量** | 少 (5-13类) | 多 (可调，50-200) |
| **数据分布** | 每个数据属多类 | 每个数据属单簇 |
| **筛选粒度** | 粗，区分度低 | 细，区分度高 |
| **筛选效率** | ~20% 数据/类 | ~2% 数据/类 |
| **新意图处理** | 理论上可覆盖 | 新意图落入噪声簇 |
| **可解释性** | 高 (有语义定义) | 低 (簇含义需解释) |
| **维护成本** | 低 | 需重新聚类 |

---

## 筛选效率公式

```
筛选效率 ∝ 1 / 类别数量

思路 A: 5 类 → 平均每类包含 20% 数据
思路 B: 50 类 → 平均每类包含 2% 数据

筛选效果: 思路 B >> 思路 A
```

---

## 思路 B 的问题

1. **簇的含义不明确**
   - Cluster 17 是什么意图？需要人工解释

2. **新问题处理困难**
   - 用户问题 "怎么办理新业务？"
   - → 落入哪个簇？可能落入噪声簇

3. **跨簇问题**
   - 用户问题可能涉及多个簇的内容
   - → 需要召回多个簇

4. **维护成本**
   - 数据更新后需要重新聚类

---

## 最终设计决策：混合架构

### 核心结论

```
┌─────────────────────────────────────────────────────────────┐
│                     设计决策                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. Speech Act 用于检索策略调整，不直接筛选数据             │
│     - 粒度太粗，无法有效区分 RAG 数据                       │
│     - 作用: 指导"怎么检索"，而非"检索什么"                  │
│                                                             │
│  2. 领域意图层才能真正区分 RAG 数据                         │
│     - 需要细粒度分类 (50+ 类)                               │
│     - 构建方式: Few-shot + 聚类发现 + 用户反馈学习          │
│                                                             │
│  3. 语义聚类提供数据组织结构                                │
│     - 作为筛选依据                                          │
│     - 作为领域意图发现的来源                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

### 混合架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                    IntentWeight 系统架构                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  用户问题                                                   │
│      │                                                      │
│      ▼                                                      │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 第一层: 意图分类 (Speech Act 5类)                    │   │
│  │   → 输出: Directive                                  │   │
│  │   → 作用: 确定检索策略 (不是筛选数据)                │   │
│  │   → 策略: 优先匹配流程类数据、关键词权重调整等       │   │
│  └─────────────────────────────────────────────────────┘   │
│      │                                                      │
│      ▼                                                      │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 第二层: 簇识别 (语义聚类)                            │   │
│  │   → RAG 数据预先聚类为 50-200 个簇                  │   │
│  │   → 问题 → 识别最相关的簇 (Top-3)                   │   │
│  │   → 作用: 缩小召回范围 (从 100% → ~6%)              │   │
│  └─────────────────────────────────────────────────────┘   │
│      │                                                      │
│      ▼                                                      │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 第三层: 语义检索                                     │   │
│  │   → 在目标簇内进行语义相似度检索                     │   │
│  │   → 应用第一层的检索策略参数                         │   │
│  │   → 返回 Top-K 结果                                 │   │
│  └─────────────────────────────────────────────────────┘   │
│      │                                                      │
│      ▼                                                      │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 第四层: 用户反馈学习                                │   │
│  │   → 收集用户反馈 (点击、满意度等)                   │   │
│  │   → 更新簇标签、检索策略权重                         │   │
│  │   → 发现新的领域意图 → 扩展第三层                   │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 各层的作用总结

| 层级 | 组件 | 作用 | 输出 |
|------|------|------|------|
| 第一层 | 意图分类 | 检索策略调整 | 策略参数 |
| 第二层 | 簇识别 | 数据范围缩小 | 目标簇列表 |
| 第三层 | 语义检索 | 精准召回 | Top-K 结果 |
| 第四层 | 反馈学习 | 持续优化 | 权重更新 |

## 关键公式

### 检索评分公式

```
Score = α × 语义相似度
      + β × 意图策略加分
      + γ × 用户反馈权重

其中:
  α = 0.6 (语义相似度权重)
  β = 0.3 (意图策略权重)
  γ = 0.1 (用户反馈权重)
```

### 筛选效率估算

```
无筛选: 召回 100% 数据
意图筛选 (5类): 召回 ~20% 数据 (区分度低)
簇筛选 (50类): 召回 ~6% 数据 (区分度高)
```
