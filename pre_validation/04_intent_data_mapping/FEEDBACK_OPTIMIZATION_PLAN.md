## 反馈信号利用方式

### 1. 簇权重调整 (推荐)

```python
# 正反馈: 提升召回该簇的概率
if feedback == "positive":
    cluster_weight[c] = min(1.5, cluster_weight[c] + α * reward)

# 负反馈: 降低召回该簇的概率  
if feedback == "negative":
    cluster_weight[c] = max(0.5, cluster_weight[c] - α * penalty)

# 召回时按加权得分选择
cluster_score = similarity * cluster_weight[c]
```

### 2. 簇边界修正

```python
# 用户修正: "这个结果不对，应该是X类"
if feedback == "correction":
    # 1. 从当前簇移除
    current_cluster.remove(sample)
    
    # 2. 加入正确的簇
    correct_cluster.add(sample)
    
    # 3. 更新簇中心
    update_cluster_centers()
```

### 3. 新簇发现

```python
# 检测大量负反馈的样本
if negative_feedback_count > threshold:
    # 触发局部重新聚类
    trigger_local_reclustering(samples)
```

## 关键发现

### 为什么静态准确率簇筛选不如纯语义？

```
纯语义检索准确率: 85.9%
簇筛选准确率: 74.0%

原因分析:
1. BGE Embedding 质量足够好
2. 簇筛选限制了召回范围
3. 静态权重(均为1.0)不够智能
```

### 反馈优化的价值

```
静态视角 (错误):
  ❌ 簇筛选比纯语义差 → 簇筛选无效

动态视角 (正确):
  ✅ 簇筛选提供了优化抓手
  ✅ 用户反馈可以调整簇权重
  ✅ 系统可以越用越好
  
关键:
  簇筛选的价值不在静态准确率
  而在于提供了一个可优化的结构
```
